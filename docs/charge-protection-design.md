# 充电保护设计（N1，实验）

状态：已实现并通过主机测试；**没有刷到设备，没有在真机上验证**（第 7 节）。测试先于代码。规则本身在 [docs/rules.md](rules.md) 的 R2、R3、K6，这份文档只写 R2 没有写到的细节，和失败模式。
标“我定的”的地方是 R2 没规定、由我选的值，请你审。

## 1. 要做什么

用户在设备上开启充电保护，选上限 80% 或 90%。电量到上限后，固件把电源芯片（AXP2101）的“电池充电使能”位关掉；电量降到回充线后，再打开。
这是实验功能（R1）：默认关，开启要二次确认，界面常驻“实验”标识，失败时回到正常充电。

## 2. 不变的规则（来自 R2、R3、K6）

| 项 | 值 |
| --- | --- |
| 预设 | 90%（回充 85%）、80%（回充 75%）。默认关；开启时默认 80%。 |
| 自定义范围 | 上限 70% 到 100%，回差不小于 5 个百分点。界面这一版只给两个预设。 |
| 判断依据 | 电量计的估算值，不用电压换算。 |
| 评估 | 每 2 秒一次。连续 3 个有效样本达到阈值才切换。普通切换至少隔 60 秒。首次启用和安全停充不受限制。回差区保持上一次已确认的状态。 |
| 硬限制 | 电池电压 ≥ 4.30 V 停充，降到 4.15 V 以下才恢复。芯片温度 ≥ 65 °C 停充，降到 55 °C 以下才恢复。优先于策略。 |
| 合理性 | 电池电压 2500 到 4600 mV，芯片温度 −40 到 150 °C。超出就当作“没读到”。 |
| 失败方向 | 电量读不到、数据过期、写入读回不一致：恢复正常充电，显示“充电保护失效，已恢复正常充电”。连恢复的写入也读回不一致：显示“无法确认充电状态”，不说“已停止”或“已恢复”。 |
| 写入 | 只写 0x18 位 1。先读到芯片型号寄存器 0x03 并确认是 AXP2101，认不出就一次不写。读出整个字节，只改这一位，写回，再读回确认。每次写都写日志（请求、读回结果、原因、时间）。 |
| 永远不做 | 提高终止电压、关闭安全定时器、绕过硬件保护。 |

## 3. 我定的细节（请审）

1. **电源芯片的寄存器在单片机复位后不变。** 电池还在，芯片就一直有电。所以停充状态会跨过重启，甚至跨过刷机。
   - 固件每次启动，先读充电使能位。读到“已关”，就先恢复充电，再让策略重新判断。启动后最多 6 秒（3 个样本）就会重新停充。
   - 刷回 0.3.1 或更早的固件不会恢复充电，因为那些固件不碰这一位。**刷旧固件之前，先在界面里关闭充电保护。** 这条要写进刷机说明。
2. **同一个样本不重复计数。** 每 250 毫秒就会调用一次，但只有采样时间变大的样本才算新样本。
3. **读不到电压或温度时**：不影响电量判断；这一项的硬限制不会触发；已经触发的限制保持，直到读到低于恢复值的新读数。（停充是偏安全的方向，所以不为这一项恢复充电。）
4. **安全停充解除后**，开关回到策略决定的状态；这一次切换要等够 60 秒间隔。
5. **写“停充”失败**：马上写“恢复”。连续 3 次停充失败，进入“故障”：不再尝试停充，一直保持正常充电，直到你重新开启或重启。一次成功的停充把计数清零。
6. **写“恢复”失败**：同一轮里最多再试 2 次（一共 3 次），之后每 30 秒试一次，直到成功。期间界面显示“无法确认充电状态”。
7. **关闭保护**立刻恢复充电，不需要确认，不受防抖和 60 秒间隔限制。保存关闭状态失败时，关闭仍然生效，界面说明“未保存”。
8. **开启保护**先保存，保存成功才开启。保存失败，保护保持关闭。
9. **没有电池**：不停充，界面说明“未检测到电池”。
10. 设置存在自己的 NVS 命名空间（`dh_chg`），读不出或格式不对就是默认值：关。不碰配对、Wi-Fi 和显示配置。
11. 状态出现在 USB 的 `status` 里（只读的 `charge` 对象），用于不看屏幕就能核对。这一版没有 USB 控制命令。`charge` 对象有：是否开启、上限、回充线、状态名、原因、是否故障、停充失败次数、开关（charging、stopped、unknown）和最近 16 次写入。`tools/provision.py --status` 只打印检查过的字段。
12. **日志（K6）**：控制台就是 USB 协议口，默认只输出警告，所以不往控制台打印。每次写入记在内存里的 16 条环形记录里（请求、结果、原因、时间），在 `status` 里能读到；同时用 info 级别写日志，开发时可以打开。**重启后环形记录丢失**，这是与“写日志”的字面要求的差别。
13. 启动时的“发现已关就恢复”不算一次切换：它不占 60 秒间隔，也不用掉“首次启用”的豁免。否则启动后要 60 秒才能重新停充。
14. 恢复失败后每 30 秒重试时只试一次（不是一轮三次）。
15. 能力 `charge_limit` 报 `support: unverified`（实验）。可用（有电池、开关读得出）时 `availability: ready`、`reason_code: EXPERIMENTAL`；否则 `unavailable`，原因 `NO_BATTERY` 或 `SWITCH_UNREADABLE`。协议没有改。

## 4. 失败模式清单

下面每一条都有一条测试。测试在 `firmware/tests/charge_test.cpp`（策略）、`board_cache_test.cpp`（寄存器写入）、`ui_model_test.cpp`（界面文字）。编号写在测试名里。

**设置**
- S1 上限 69、101 被拒；70、100 被接受。
- S2 回差 4 被拒；5 被接受；回充线 0 被拒。
- S3 序列化再解析得到同一份设置。
- S4 坏文本（空、字段多或少、非数字、负数、过长数字、空白）解析成默认值（关）。
- S5 写着“开”但数字无效：结果是关，不是开。

**读数**
- R1 样本过期（超过 6 秒）、从未采样、来自未来：不可用。
- R2 没有电池、电池状态未知：不可用。
- R3 电量 −1、101、读取出错：不可用；0 和 100 可用。
- R4 电压 2499、4601，温度 −41、151：当作没读到，电量照常用。
- R5 电源芯片故障：不可用。
- R6 同一个采样时间的样本不重复计数。

**策略**
- P1 低于上限时不写任何东西。
- P2 达到上限要连续 3 个新样本；2 个不够；中间一个低于上限的样本清零。
- P3 刚好等于上限就算达到；少 1 个百分点不算。
- P4 回差区保持原状态（充电中和停充中各一条）。
- P5 刚好等于回充线才算；要连续 3 个新样本。
- P6 切换后 60 秒内，相反方向不切换，即使已经有 3 个样本；到 60 秒就切换。
- P7 首次启用不受 60 秒限制（电量已超过上限，3 个样本后就停）。
- P8 关闭保护立刻恢复充电，没有防抖，没有间隔。
- P9 开启时改了上限，按新上限判断。

**硬限制**
- H1 电压 4300 立刻停充（没有防抖，没有间隔）；4299 不停。停充后 4150 仍然停，4149 才解除。
- H2 温度 65.0 停充；64.9 不停。停充后 55.0 仍然停，54.9 才解除。
- H3 电量低于上限，硬限制照样停充。
- H4 解除后由策略决定：电量在上限以上仍然停，在回充线以下恢复。
- H5 保护关闭时，硬限制不写任何东西。
- H6 电压和温度是两个独立的锁；一个解除，另一个还在，仍然停充。
- H7 读不到电压时，已触发的电压限制保持。

**失败方向**
- F1 停充中样本过期：马上恢复充电，状态“失效”。
- F2 停充中电量读不到：马上恢复充电。
- F3 没有电池：不停充；停充中则恢复。
- F4 读数恢复后，要 3 个新样本，并且要等够 60 秒间隔，才再停充。
- F5 本来就在充电时读数不可用：不写，但状态显示“失效”。
- F6 写停充失败：马上写恢复；状态“失效”。
- F7 停充读回不一致：马上写恢复。
- F8 连续 3 次停充失败进入故障：之后不再尝试停充。
- F9 一次成功的停充把失败计数清零。
- F10 恢复也失败：状态“无法确认”；同一轮最多 3 次，之后每 30 秒一次；不说“已停止”或“已恢复”。
- F11 恢复最终成功：状态回到“失效，已恢复”。
- F12 启动时读不到开关：状态“无法确认”，不写“停充”。

**启动**
- B1 启动时发现充电已关：先恢复充电，不管保护开还是关。
- B2 启动时发现充电已开：不写。
- B3 恢复之后，策略照常判断；电量在上限以上，3 个样本后再停。

**日志**
- L1 每次停充和恢复都有一条记录：请求、结果、原因、时间。
- L2 没有写入就没有记录。

**不变量（随机游走，一百万步）**
- I1 保护关闭时，从不写“停充”。
- I2 读数不可用时，从不写“停充”。
- I3 一个读数不可用的步骤之后，开关是“充电”（除非写入失败，此时状态是“无法确认”）。
- I4 两次普通切换之间至少 60 秒。
- I5 “停充”的写入之前，要么有 3 个新样本达到上限，要么有硬限制。

**寄存器写入（board，`board_cache_test.cpp` 里编号 C1 到 C10）**
- C1 只改位 1；其余 7 位（包括位 3 电量计）保持原值。
- C2 已经是目标值时不写。
- C3 芯片型号不是 AXP2101，或不应答：一次都不写，连 0x18 也不读。
- C4 0x18 读不出来：不写。
- C5 写失败和芯片忽略写入（读回不同）给出不同的结果，各写一次。
- C6 读回读不出来：算“未确认”。
- C7 开关的当前值可以读出来，而且只信认得出型号的芯片。
- C8 采样代码从不写 0x18，开关停着也不去“修”。
- C9 充电写入不碰其他寄存器。
- C10 板子没初始化好：拒绝，不碰空的互斥锁。

**界面（ui_model）**
- U1 各状态的文字、颜色（正常、警告）和所有字都在字库里。
- U2 保护关闭：按钮是“开启…”，可点；保护开着：按钮是“关闭”。
- U3 没有电池或开关读不出来：按钮禁用，写明原因。
- U4 “实验”标识在每个状态都显示。

## 6. 这一版不做

- 自定义上限的界面（只有 80% 和 90%）。
- USB 命令开关充电保护。
- 把充电保护状态上报给 Agent。
- 刷机。真机验证要放电到阈值以下，要你在场。

**没有做、没有验证：**
- **没有刷到设备。** 设备上跑的仍是不带充电保护的 0.3.1。

- **没有在真机上停过充电。** 0x18 位 1 是否真的能停充、停充时电源芯片的反应、再充时的行为，都只在主机的假芯片上测过。
- 真机验证要放电到阈值以下，要你在场，可能要几个小时。
- 没有测过断电、重启、刷机发生在停充期间的情况。固件的做法是启动先恢复；但**刷回 0.3.1 或更早的固件不会恢复**（那些固件不碰这一位）。刷旧固件之前先在界面里关闭充电保护，已写进 [flashing.md](flashing.md)。
- 没有 USB 控制命令；没有自定义上限的界面；没有把状态上报给 Agent。
- 环形日志重启后丢失。
