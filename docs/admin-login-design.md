# 管理员登录的设计（规则 R8）

状态：**已实现**，Agent 端的测试全过；网页管理台的登录页见 [web 管理台](web-console-design.md)。没有在真机或真浏览器里长期使用过。

## 流程

1. `deskhubctl admin-token` 生成口令，只显示一次。
2. 第一次在浏览器里用口令登录。得到的是**设置会话**：只能设置密码，其余管理接口都返回 403 `PASSWORD_REQUIRED`。
3. 设置密码。成功后换新的 Cookie 和 CSRF，这个会话变成**密码会话**。
4. 以后用密码登录。浏览器带 Origin 的口令登录从此返回 403 `TOKEN_LOGIN_DISABLED`。
5. 命令行和脚本（不带 Origin、来自本机）仍然可以用口令。这是**脚本会话**：权限和以前一样，但不能设置或修改密码。口令被吊销或替换时，脚本会话结束；密码会话不受口令影响。
6. 忘记密码：在运行 Agent 的电脑上执行 `deskhubctl admin-password-reset`。它清除密码和锁定，所有网页会话立即失效；之后回到第 2 步。网页上没有“忘记密码”，口令也不能重置密码。

## 密码与锁定

| 项目 | 做法 |
| --- | --- |
| 规则 | 12 到 128 个字符（按 NFKC 规范化后数）；拒绝常见密码、常见词加数字、不同字符不超过 3 个、8 个以上的连续字符（abcdefgh、87654321）、控制字符、只有空白、口令本身 |
| 保存 | scrypt，N=2^17、r=8、p=1，16 字节随机盐；参数和哈希一起存，以后提高成本不会让旧密码失效 |
| 锁定 | 连续 5 次失败，锁 15 分钟；第 5 次返回 401，第 6 次起返回 429 `ACCOUNT_LOCKED`，哪怕密码是对的。成功登录清零 |
| 持久 | 失败计数和锁记在数据库里；重启不清 |
| 出错时 | 读不到锁记录、存储出错、哈希参数不对：一律拒绝（503 或 429），不放行（K1）。读不懂的锁时间当作还在锁 |
| 并发 | 一次只算一个密码（每次 128 MiB 内存）；计数在同一把锁里读、改、写，所以 24 个同时的错误尝试正好是 5 个 401 加 19 个 429 |
| 时间 | 没有设置密码时，登录也照样算一遍哈希，答案和密码错一样（401 `LOGIN_FAILED`） |
| 限流 | 网页登录每个来源地址每分钟 10 次，先于哈希检查 |
| 会话 | 30 分钟，HttpOnly、SameSite=Strict，https 时加 Secure；写操作检查同源和 CSRF；设置、修改、重置密码都让更早的会话立即失效（会话记着密码的“代数”，每次请求和数据库比较） |
| 不泄露 | 密码不出现在任何响应、错误、日志和数据库文件里；验证错误不回显输入 |

## 失败模式和测试

测试在 `agent/tests/test_admin_password.py`，编号对应下表。变异检查：`scripts/mutation/admin_password.py`（64 条）。

| 编号 | 失败模式 |
| --- | --- |
| A | 弱密码、过长过短、非文字、控制字符、只有空白、口令本身被接受 |
| H | 盐固定或太短、成本太低、不同写法的同一段文字被当成不同密码、用现在的成本而不是保存的成本验证、明文入库 |
| S | 设置会话能用其他页面（包括固件上传）；脚本被当成网页；设置密码不检查 CSRF 和同源；弱密码结束了设置；口令被吊销后设置会话还活着；设置会话能替换已有的密码 |
| T | 设置密码后浏览器还能用口令登录；口令被吊销后密码会话跟着死 |
| L | 密码登录不检查同源；错误和“没设置密码”的回答不同；5 次失败不锁；锁不持久；成功不清零；锁时间读不懂就放行；存储出错就放行；并发尝试绕过计数；限流在哈希之后；锁过期后计数没有重新开始 |
| C | 修改不需要当前密码；错的当前密码不计入失败；弱的新密码消耗一次尝试；新密码与旧的相同；其他会话没有结束；口令被用作新密码 |
| R | 网页或脚本能重置或设置密码；重置不结束会话、不清锁 |
| N | 密码出现在响应、错误、日志、数据库里 |

## 没有验证的

- 没有在真正的浏览器里走过一遍（网页管理台做完以后才有页面）。
- scrypt 的耗时只在测试里用小参数跑过；N=2^17 在这台电脑上大约几分之一秒，没有在低配电脑上量过。
- 密码规则里的常见词表是内置的一小张表，不是完整的泄露库。
