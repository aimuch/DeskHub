# 规则

状态：2026-10-28 定稿。范围见 [product-scope.md](product-scope.md)。

- **K 开头**：保留的规则，不放宽。
- **R 开头**：放宽的规则，并写明用什么保护来代替。
- 改 K 规则，要你明确决定。改 R 规则，要单独提交并写明原因。

## 1. 保留的规则

**K1 信任链。**
设备到 Agent 用 TLS：私有 CA，不关闭证书链、主机名和有效期检查。
每台设备有独立令牌，可以单独吊销。
OTA 必须签名（ECDSA P-256、SHA-256），用双槽并带回滚。
签名公钥已经写进设备。换信任根，所有设备都要重新配对，所以这要单独决定。

**K2 命令安全。**
没有任意命令、脚本或由参数组成的地址。
显示器按 UUID、序列号、注册路径绑定；动作是白名单。
命令不自动重试。结果“未确认”时，不当成成功。

**K3 不伪造数据。**
未知就显示未知，过期就显示过期，都不显示成 0。
只有读回的结果和目标一致，才写“已确认”。没有读回证据，写“已发送（未确认）”。

**K4 密钥与秘密。**
`.state/` 和私钥不进 git。签名私钥只给签名工具用。
Wi-Fi 密码只用隐藏输入。令牌不进命令行参数、日志和网址。秘密文件权限 0600，不是符号链接。

**K5 显示保护。**
夜间限亮、故障限亮、临界电量限亮、手动关屏、亮度 0 都保持有效。
关屏后的第一次触摸只唤醒，不触发动作。烧屏保护保留。

**K6 电源芯片写入要有记录。**
每次写：先读，再改，写后读回确认，并写日志。只能写 R3 白名单里的位。

**K7 基线文件。**
`README.md` 列出的安全基线文件，改动要单独提交，写明原因，并补测试。

## 2. 放宽的规则

### R1 功能的三种状态

旧规则：没验证就不开放。
新规则：每个功能是“已验证”“实验”或“不可用”三种状态之一。

- **已验证**：有测试或实测证据，默认可用。证据记在功能表里。
- **实验**：默认关。开启要二次确认。界面常驻一个标识。失败时必须回到安全默认值。它不能影响其他功能，并且要写日志。
- **不可用**：界面保留入口，写出原因代码。不隐藏。

不能把“实验”写成“已验证”。

### R2 充电保护（N1，实验）

旧规则：五个条件全部验证后才开放。
新规则：作为实验功能开放，用下面的保护代替。

**策略**

| 项 | 值 |
| --- | --- |
| 预设 | 90%（回充 85%）、80%（回充 75%）。默认 80%。 |
| 自定义 | 上限 70% 到 100%，回差不小于 5 个百分点。 |
| 判断依据 | 电量计的估算值，不用电压换算。 |
| 评估频率 | 每 2 秒一次。 |
| 防抖 | 连续 3 个有效样本达到阈值才切换。 |
| 最小间隔 | 普通切换至少隔 60 秒。首次启用和安全停充不受限制。 |
| 回差区 | 保持上一次已确认的状态。 |

**本地硬限制，优先于策略**

| 条件 | 动作 |
| --- | --- |
| 电池电压不小于 4.30 V | 停充，降到 4.15 V 以下才恢复 |
| 芯片温度不小于 65 °C | 停充，降到 55 °C 以下才恢复 |

**合理性检查**

读数超出下面的范围，就当作“没读到”：电池电压 2500 到 4600 mV，USB 电压 3000 到 6500 mV，芯片温度 −40 到 150 °C。

**失败方向（D6）**

电量读不到、数据过期、或者写入的开关读回不一致：恢复正常充电，由电源芯片自己的终止机制兜底。屏幕显示“充电保护失效，已恢复正常充电”。
如果连恢复充电的写入也读回不一致，就显示“无法确认充电状态”，不说“已停止”或“已恢复”。

**显示**

保护开着时，屏幕常驻“充电保护中：上限 80%”。每次停充和恢复都写日志：请求、读回结果、原因、时间。

**永远不做**

提高终止电压、关闭安全定时器、绕过硬件保护，来实现上限。

### R3 电源芯片写入白名单（D5）

旧规则：固件只读电源芯片。
新规则：只允许写下面几位。没有这些，读不到电池电压、芯片温度和电量。

| 寄存器 | 位 | 作用 | 什么时候写 |
| --- | --- | --- | --- |
| 0x30 | 位 0、2、4 | 打开电池电压、USB 电压、芯片温度的 ADC | 启动时，如果这几位是 0 |
| 0x68 | 位 0 | 打开电池检测 | 启动时，如果这位是 0 |
| 0x18 | 位 3 | 打开电量计 | 启动时，如果这位是 0 |
| 0x18 | 位 1 | 充电使能 | 只在充电保护开启时 |

来源是 SmartHub 的 `power.c`，它对应微雪的例程。**实现前，必须再用 XPowersLib 和 AXP2101 手册逐位核对。** 核对结果记在代码注释和本表里。

做法：读出整个字节，只改这一位，写回，再读回确认。读回不一致就记日志，并显示该测量“不可用”。

**以下一律不写，除非另行批准：** 充电电压与终止电压（0x64）、TS 引脚设置（0x50，以及 0x30 位 1）、充电电流、充电定时器、BATFET、保护阈值、电源轨。

### R4 平台声明（D2）

旧规则：必须实际适配并有矩阵，才能声明支持一个平台。
新规则：只声明已经验证过的平台，目前只有 macOS。其他平台标“未验证”，不挡发布。

### R5 版本与发布

版本号不带后缀（`主.次.修订`）。
验证状态写在功能表里，不靠版本号表示。
有“实验”或“未验证”的项，只要标清楚，就不挡发布。

### R6 管理台访问

保留 HTTPS 和管理员令牌。减少麻烦的办法：

- 提供“信任证书”脚本。它要你确认，并输入系统密码，由你自己执行。
- 提供本机回环选项：`http://127.0.0.1`，不带证书，设备连不上。
- Agent 启动时打印完整的管理台地址，包括 `/manage/`。

### R7 首次配网（D8）

“长按按键进入配网页”必须满足：

1. 人在设备旁。只在设备未配对，或用户长按按键时开启。
2. 有时限，默认 5 分钟，到时自动关闭。
3. 一次性验证码显示在设备屏幕上，页面要求输入它。没有默认密码。
4. 只在设备自己的临时热点上可达，不接入局域网。
5. 配网页写入的内容，走和 USB 配对同一条保存路径，K1 和 K4 照旧。

这个功能要先设计，再按 K1 审一遍，然后才实现。

## 3. 永远不做

- 提高充电终止电压、关闭安全定时器、绕过硬件保护。
- 把设备或 Agent 的端口暴露到公网。
- 任意 shell、脚本，或由参数组成的任意地址。
- 用电压线性换算冒充电量百分比。
- 把芯片温度说成电池温度。
- 默认出厂密码，或者用主机名当秘密。

## 4. 改这份文件

- 改 K 规则：要你明确决定，单独提交。
- 改 R 规则：单独提交，写明原因，并更新范围文档里的相关项。
- 新增“实验”功能：先写进范围文档，并写出它的失败方向。
