# 0.3.9 键盘显示损坏调查

日期：2026-11-03。

## 已知现象

用户在刷入 0.3.9 后提供照片 IMG_6318.HEIC。键盘页出现横向条带、字母缺笔和旧页面内容残留。中文与 ASCII 字母都有显示损坏。不能仅据此认定是字库问题。

USB 已读回版本 0.3.9、`ui_alive: true`。这只证明界面任务报告存活，不证明面板正确显示。设备方向为 180°，主题为 ocean。刷机镜像校验成功。

## 修复前要排查的失败方式

- 局部刷新窗口和像素缓冲区尺寸不一致。
- 旋转后刷新坐标与物理面板方向不一致。
- DMA 尚未完成时，绘制任务复用缓冲区。
- SPI 传输分块、长度或时钟导致像素数据丢失。
- 界面层未覆盖旧内容，或对象更新没有触发正确重绘。

## 验证要求

主机预览使用模拟面板，不能覆盖 ESP32 的 SPI 和 DMA 路径。修复必须说明具体代码原因，并核对键盘、页面切换、大小写切换和密码显示后的重绘。真实屏幕是否恢复正常，需要设备旁观察；不能由 USB 状态代替。

用户随后补充：上一版本已经出现同样问题。因此它是既有显示故障，不能归因于新增软键盘。

## 整行刷新对照（0.3.10）

仅改变刷新区域策略：在 `LV_EVENT_INVALIDATE_AREA` 阶段将 x 扩展为 0–479，y 保留原覆盖范围并按 CO5300 要求向外对齐到偶数行。保持 180°、QSPI 时钟、像素格式、缓冲区数量和键盘布局不变。每个刷新块仍由原适配器按缓冲区大小分块；不直接发送整屏大缓冲。

这是一项诊断对照。若条带消失，只能先说明小窗口刷新路径值得继续调查；不能据此确认具体根因。若条带仍存在，再检查传输时序和实际发送像素。

先列出失败方式，并在板级主机检查中验证：回调未注册、窄窗口未扩展、纵向范围变化、奇数边界未对齐。第一次运行以 `full-width diagnostic callback missing` 失败。加入回调后，15 组固件主机检查全部通过。这不证明真机显示已修复。

当前状态：0.3.10 已完整构建，无编译警告；已刷入并完成四个镜像校验，USB 读回版本 0.3.10、ui_alive true，主题 ocean、旋转 180、配置版本 37 保留。用户反馈“仍有乱码”，随后补充“现在所有页面都是横纹乱码了”。整行刷新没有消除故障，不能认定修复；下一版撤回整行刷新。见 [0.3.10 证据](firmware-0.3.10.json)。

## 恢复原刷新范围并降频（0.3.11）

撤回 0.3.10 的整行失效区回调，恢复 0.3.9 的局部刷新范围。相对 0.3.9 的显示配置，仅把 LCD QSPI 时钟上限从 40 MHz 改为 20 MHz；保留旋转、像素格式、队列和双缓冲配置。不修改 managed_components，而是在本项目中包装 LCD SPI 创建调用。

失败方式先于实现写入检查：40 MHz 未降低、低时钟被提高、原配置被修改、其他配置或句柄被改变、驱动错误被掩盖、空配置导致崩溃。首次编译因包装实现文件尚不存在而失败。实现后 16 组固件主机检查通过。

0.3.11 已刷入并读回，但串口连续报告 `spi_common: spicommon_dma_setup_priv_buffer(430): Failed to allocate priv TX buffer`，随后出现 `lcd_panel.io.spi: panel_io_spi_tx_color(406): spi transmit (queue) color failed`。见 [实际驱动错误](firmware-0.3.11-display-errors.json)。降频没有消除错误。

## 已确认的传输失败与修复（0.3.12）

BSP 把 SPI 总线最大事务设为 480×480×2 字节，LVGL 使用 PSRAM 双缓冲，每块最多 480×50×2 = 48000 字节。当前驱动没有启用 PSRAM 直接 DMA。IDF 因此在 `spicommon_dma_setup_priv_buffer` 中为每个待发块分配连续内部 DMA 缓冲区；真机日志确认此处的 TX 分配失败。屏幕驱动随即拒绝入队该块，留下未刷新的旧像素。

0.3.12 撤回临时降频，恢复原局部刷新和 40 MHz。仅把 LCD 所在 SPI2 总线的 DMA 最大事务限定为 4092 字节。IDF 屏幕驱动原有的分块循环会保持 CS 并继续发送剩余像素，最后一块才发完成回调。最多 3 个在途事务的临时 TX 空间因此约为 12 KB，而不是逐块请求约 48 KB 连续空间。不修改 managed_components，不改变像素内容、方向、字库或 LVGL 双缓冲。

失败方式先于实现写入 `display_transfer_test.cpp`：大块未限制、小块被提高、原始配置或引脚被改变、其他总线或无 DMA 路径被改变、空配置崩溃、错误被吞。首次因实现文件尚不存在而编译失败；实现后 16 组固件主机检查通过。

0.3.12 已刷入。30 秒串口采样未再收到 DMA TX 分配失败或像素入队失败，但记录到启动阶段的两条新错误：`Cannot acquire bus when a polling transaction is in progress` 和 `acquire spi bus failed`。见 [0.3.12 驱动日志](firmware-0.3.12-display-errors.json)。

## 启动命令与刷新任务互斥（0.3.13）

BSP 的 `bsp_display_start_with_config` 在返回前已启动 LVGL 任务。本项目在返回后立即发送物理旋转和亮度命令，但没有获取显示锁，可能与该任务的 SPI 传输冲突。0.3.13 在这两条命令前获取现有 `esp_lv_adapter_lock`，并用作用域守卫在所有退出路径解锁；亮度失败也返回错误，避免显示初始化失败却报告就绪。运行时旋转和亮度原本已在 LVGL 任务内执行。

检查先于修复写入：锁失败不能发送命令、旋转或亮度失败必须解锁并保持不可用、成功必须解锁。修复前以 `unlocked display rotation command` 失败；修复后 16 组固件主机检查通过。

当前状态：0.3.13 已构建、打包并刷入，四个镜像校验通过，16 组主机检查通过，无编译警告。保留 DMA 分块修复，恢复原刷新范围、40 MHz 和既有 180° 设置。30 秒串口采样未记录此前的 DMA 分配、像素入队或启动总线冲突错误；USB 读回版本 0.3.13、ui_alive true、主题 ocean、旋转 180、配置版本 37。Wi-Fi 已连接，Agent 仍未配对，provision_revision 为 1；未据此推断谁通过何种流程配置了 Wi-Fi。2026-11-03 用户回复“显示正常”，本次横纹故障已得到真机确认。长期稳定和其他功能仍需各自证据。见 [0.3.13 证据](firmware-0.3.13.json)。
